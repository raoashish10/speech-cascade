# Packages in deploy/requirements-chatterbox.txt that docker/triton/Dockerfile
# must NOT install into /venv/chatterbox.
#
# WHY: /venv/chatterbox exists to isolate chatterbox-tts's conflicting
# dependency pins from the main TensorRT-LLM stack. It does NOT need its own
# copy of CUDA. Measured on a real pod, the venv was 8.0GB, of which:
#
#   nvidia/*    4.7 GB   a second full CUDA 12.8 wheel set
#   torch       1.6 GB   a second full torch
#   triton      0.6 GB   a second OpenAI-Triton
#   everything chatterbox actually needs   ~1.1 GB
#
# So ~6.9GB of the 8.0GB was a duplicate GPU stack. The Dockerfile now points
# this venv at the main environment's torch with a .pth bridge instead (see
# the chatterbox RUN there), keeping the venv for exactly what it was for:
# chatterbox-tts's own conflicting non-torch pins.
#
# This is the same trade-off the Dockerfile already makes elsewhere and is not
# a new kind of risk: chatterbox-tts==0.1.7 hard-pins torch==2.6.0, which this
# deployment has always overridden (it is installed --no-deps against a much
# newer torch). Having already decided not to honor that pin, honoring it
# twice -- once per venv -- buys nothing.
#
# --- provided by the main environment via the .pth bridge -----------------
# The base image ships torch 2.10.0a0+b4e4ee81d3.nv25.12 (NVIDIA's CUDA 13
# build) and triton 3.5.1. torchaudio is NOT in the base image and is
# installed explicitly by the Dockerfile at a version matching that torch --
# it is deliberately excluded here so the +cu128 pin below cannot drag the
# cu12 stack back in.
torch
torchaudio
torchcodec
triton

# The cu12 wheel set -- the base image provides CUDA 13.1 system libraries.
#
# ONE EXCEPTION, found by running the thing rather than reasoning about it:
# cuDNN is NOT excluded in practice. The Dockerfile installs
# nvidia-cudnn-cu13 explicitly right after torch, because the base image
# ships cuDNN 9.17.0 while torch 2.11.0+cu130 is compiled against 9.19.0,
# and torch refuses to run its RNN kernels on a mismatch:
#
#   RuntimeError: cuDNN version incompatibility: PyTorch was compiled
#   against (9, 19, 0) but found runtime version (9, 17, 0)
#
# which took chatterbox_tts to UNAVAILABLE ("chatterbox worker failed to
# start") because its s3gen voice encoder uses LSTMs.
#
# Worth remembering WHY this was missed: `pip check` did warn that torch
# required nvidia-cudnn-cu13, and that warning was dismissed after `ldd`
# showed no unresolved libraries in libtorch_cuda.so. That was bad
# evidence -- cuDNN is dlopen'd lazily at first use, so it never appears
# in ldd output, and no amount of static inspection would have caught it.
# The libraries below are genuinely unused by this deployment (no
# torch.distributed, no sparse ops, no multi-GPU), but "ldd is clean" is
# not what establishes that; running the model is.
nvidia-cublas-cu12
nvidia-cuda-cupti-cu12
nvidia-cuda-nvrtc-cu12
nvidia-cuda-runtime-cu12
nvidia-cudnn-cu12
nvidia-cufft-cu12
nvidia-cufile-cu12
nvidia-curand-cu12
nvidia-cusolver-cu12
nvidia-cusparse-cu12
nvidia-cusparselt-cu12
nvidia-nccl-cu12
nvidia-npp-cu12
nvidia-nvjitlink-cu12
nvidia-nvshmem-cu12
nvidia-nvtx-cu12
