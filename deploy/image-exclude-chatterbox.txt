# Packages in deploy/requirements-chatterbox.txt that docker/triton/Dockerfile
# must NOT install into /venv/chatterbox.
#
# WHY: /venv/chatterbox exists to isolate chatterbox-tts's conflicting
# dependency pins from the main TensorRT-LLM stack. It does NOT need its own
# copy of CUDA. Measured on a real pod, the venv was 8.0GB, of which:
#
#   nvidia/*    4.7 GB   a second full CUDA 12.8 wheel set
#   torch       1.6 GB   a second full torch
#   triton      0.6 GB   a second OpenAI-Triton
#   everything chatterbox actually needs   ~1.1 GB
#
# So ~6.9GB of the 8.0GB was a duplicate GPU stack. The Dockerfile now points
# this venv at the main environment's torch with a .pth bridge instead (see
# the chatterbox RUN there), keeping the venv for exactly what it was for:
# chatterbox-tts's own conflicting non-torch pins.
#
# This is the same trade-off the Dockerfile already makes elsewhere and is not
# a new kind of risk: chatterbox-tts==0.1.7 hard-pins torch==2.6.0, which this
# deployment has always overridden (it is installed --no-deps against a much
# newer torch). Having already decided not to honor that pin, honoring it
# twice -- once per venv -- buys nothing.
#
# --- provided by the main environment via the .pth bridge -----------------
# The base image ships torch 2.10.0a0+b4e4ee81d3.nv25.12 (NVIDIA's CUDA 13
# build) and triton 3.5.1. torchaudio is NOT in the base image and is
# installed explicitly by the Dockerfile at a version matching that torch --
# it is deliberately excluded here so the +cu128 pin below cannot drag the
# cu12 stack back in.
torch
torchaudio
torchcodec
triton
